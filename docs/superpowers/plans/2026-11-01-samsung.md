# Samsung Tizen TV Lane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add, pair and control Samsung Tizen TVs (2016 and later) from the one remote, over the home
Wi-Fi, with no change to the screens beyond a Samsung "turn on" hint.

**Architecture:** `src/samsung` is a sibling of `src/webos`, pure TypeScript behind `TvTransport`. It
reads the TV's plain-HTTP info page (name, model, MAC, power) through `transport.request`, and sends
keys over one pinned `wss://<ip>:8002` WebSocket. It registers as one `BrandSetup` (discovery, probe,
pairing, rediscovery by MAC) and one `LinkDriver`; the hub, screens and store learn nothing new.
Power state comes only from polling the info page, every 5 s while observed.

**Tech Stack:** Expo SDK 58, TypeScript, Jest, Bun. No native work: everything needed (`wss` open with
TOFU/pin, `request`, `ssdpSearch`, `probe`, `sendWol`) lands in the groundwork plan.

**Spec:** `docs/superpowers/specs/2026-11-01-every-tv-design.md` (§4, §5.1, §5.3, §5.4, §5.5 items 2–3,
§7), on top of `docs/superpowers/plans/2026-11-01-tv-core.md` (lands first; its Interfaces are frozen)
and `docs/research/2026-11-01-tv-protocols.md` §2 (protocol facts).

**Prerequisite:** `docs/superpowers/plans/2026-11-01-tv-core.md` is merged into this lane's base
(`lane/tv-core` → `main`). Before Task 1, check that `src/tv/brands.ts` exports `BrandSetup`,
`src/tv/setup.ts` exports `createCompositeTvSetup`, `TvTransport.request` exists, and
`createServices` has the `// <lane> brand` and `// <lane> lane` slot comments. If a comment is
missing, add `// samsung brand` / `// samsung lane` in the place the core plan describes.

## Review Focus

Failure modes the spec implies but the groundwork tests do not exercise, most likely first. Each has
a named test in the owning task.

1. **TV in standby.** The info page still answers with `PowerState: "standby"` but the WebSocket is
   refused. Expected: Home shows it off, the driver opens no socket and does not reconnect in a
   loop. Task 5.
2. **Token revoked on the TV** (removed in the TV's device list, or "Access notification" reset). The
   TV prompts again. Expected: one "Pair the TV again" error, then no further prompts on the TV
   until the user re-pairs. Task 5.
3. **Another device at the old address after a DHCP change**, or the TV's certificate changing.
   Expected: never adopt a host whose `wifiMac` differs; a pin mismatch at the same host asks to pair
   again rather than silently trusting the new certificate. Tasks 4 and 5.
4. **Something else on port 8001/8002** (a router, a NAS, a Chromecast) or an info page that is not
   Samsung's. Expected: not listed as a TV, `probeHost` returns null. Task 4.
5. **Text that is empty, non-ASCII or has an emoji**, and a text field that is not open on the TV.
   Expected: UTF-8 base64, never a crash; the TV ignores it. Task 1.

  // keys.ts
  export const KEY_NAME: Record<Exclude<TvKey, 'playPause'>, string>;
  export const PLAY_PAUSE_CYCLE: readonly ['KEY_PAUSE', 'KEY_PLAY'];

  // frames.ts
  export function keyFrame(keyName: string): string;      // JSON text
  export function textFrame(text: string): string;        // JSON text, SendInputString
  export type SamsungEvent =
    | { event: 'ms.channel.connect'; token: string }      // '' when the TV sends none
    | { event: 'ms.channel.unauthorized' }
    | { event: 'ms.channel.timeout' }
    | { event: 'ms.error'; message: string }
    | { event: 'other' };

  export interface SamsungInfo { name: string; model?: string; mac?: string; power: 'on' | 'standby' }

  // url.ts
  export const INFO_PORT = 8001; export const WSS_PORT = 8002;
  export const APP_NAME = 'One Remote';
  export function socketUrl(host: string, token: string): string;
  export function infoUrl(host: string): string;                   // http://<host>:8001/api/v2/

- Values (spec §5.3, research §2). **Keys:**
  - up, down, left, right → `KEY_UP`, `KEY_DOWN`, `KEY_LEFT`, `KEY_RIGHT`;
  - ok → `KEY_ENTER`; back → `KEY_RETURN`; home → `KEY_HOME`; mute → `KEY_MUTE`;
  - volumeUp → `KEY_VOLUP`; volumeDown → `KEY_VOLDOWN`;
  - input → `KEY_SOURCE` (the TV's own picker); power → `KEY_POWER` (toggle).
- **Play/pause (builder's pick, confirm on first Samsung run):** alternate `KEY_PAUSE`, `KEY_PLAY`,
  starting with `KEY_PAUSE`, the same rule as LG's `nextPlayPause`. Reason: the published Samsung key
  lists have no single play/pause toggle key (`KEY_PLAY_BACK` is a different key), and two explicit
  keys never get the state wrong twice in a row on the TV's own player.
- **Key frame:** `{"method":"ms.remote.control","params":{"Cmd":"Click","DataOfCmd":"<KEY>","Option":"false","TypeOfRemote":"SendRemoteKey"}}`.
- **Text frame** (confirm on first run whether the TV appends or replaces):
  `{"method":"ms.remote.control","params":{"Cmd":"<base64(UTF-8 text)>","DataOfCmd":"base64","Option":"true","TypeOfRemote":"SendInputString"}}`.
  Base64 is of the UTF-8 bytes, via a small helper in `frames.ts` that uses `btoa` over a byte string.
- **Socket URL:** `wss://<host>:8002/api/v2/channels/samsung.remote.control?name=<encodeURIComponent(base64("One Remote"))>`
  plus `&token=<encodeURIComponent(token)>` only when `token` is non-empty.
- **Info page** (`GET http://<host>:8001/api/v2/`, JSON with a `device` object): `name` ← `device.name`
  (fallback `'Samsung TV'`); `model` ← `device.modelName`; `mac` ← `device.wifiMac` normalised to
  lower-case colon form (null-ed if it does not match a MAC); `power` ← `'standby'` only when
  `device.PowerState === 'standby'`, else `'on'` (older firmware omits the field). `parseInfo` returns
  null unless the body is JSON with a `device` object that has a string `modelName` or a `type`
  starting with `Samsung` (Review Focus 4). `fetchInfo` throws `DeviceError('notSent')` for a non-200
  status or a body `parseInfo` rejects; transport errors pass through unchanged.

### Task 3: WebSocket client and pairing

**Files:**

- Create: `src/samsung/client.ts`, `src/samsung/pair.ts`.
- Test: `tests/samsung/client.test.ts`, `tests/samsung/pair.test.ts`.

**Interfaces:**

- Consumes: Task 1 (`socketUrl`, `keyFrame`, `textFrame`, `parseEvent`, `fetchInfo`), Task 2 fakes,
  `PairError`, `PairPrompts`, `FoundTv`, `PairedTv`, `TvLink` (core).
- Produces (exact):

  ```ts
  // client.ts
  export class SamsungClient {
    /** Opens the wss socket only; does not wait for the TV's answer. `token: ''` or absent: no token. */
    static connect(t: TvTransport,
      o: { host: string; token?: string; pinSha256?: string; pairing?: boolean },
      timeoutMs: number): Promise<SamsungClient>;
    /** The pin passed in, or the certificate seen while pairing. */
    readonly certSha256: string | undefined;
    /** Resolves the token ('' when the TV sends none) on ms.channel.connect.
     *  Rejects DeviceError('notPaired') on ms.channel.unauthorized / ms.channel.timeout / ms.error
     *  mentioning "unauthorized", 'timeout' after `timeoutMs`, 'notSent' if the socket closes first. */
    ready(timeoutMs: number): Promise<string>;
    /** Resolves immediately once written (the TV does not acknowledge). Throws 'notSent' when closed. */
    key(keyName: string): void;
    text(text: string): void;
    onClose(cb: () => void): void;
    close(): void;
  }

  // pair.ts
  export function pairSamsung(
    t: TvTransport, secrets: TvSecretsWithDelete, tv: FoundTv, prompts: Pick<PairPrompts, 'onAllow'>,
    opts?: { reuse?: Extract<TvLink, { kind: 'samsung' }>; promptMs?: number /* 60000 */;
             allowDelayMs?: number /* 400 */ },
  ): Promise<PairedTv>;
  ```

- Pairing rules: (1) `fetchInfo` first; failure → `PairError('unreachable')`, a `notLocal`
  `DeviceError` is rethrown. (2) `SamsungClient.connect` with `{pairing: true}`, 3000 ms; failure →
  `unreachable`; no `certSha256` → `unreachable`. (3) Call `prompts.onAllow()` once, but only if the
  TV has not answered within `allowDelayMs` (a TV set to allow all never shows the prompt, and the
  screen should not flash "Press Allow"). (4) `ready(promptMs)`: `notPaired` → `PairError('denied')`;
  `timeout` → `PairError('timeout')`; other → `unreachable`. (5) Store the token under
  `reuse?.tokenRef ?? 'samsung:<random>'` with `secrets.set` (an empty token is stored as `''`; the
  driver treats `null`, not `''`, as "unpaired"); a failing set → `unreachable`. (6) Return
  `{ link: {kind:'samsung', host, mac?, tokenRef, pinSha256: certSha256}, suggestedName: info.name }`,
  with `mac` from the info page. The client is always closed.

  export function parseSsdpReply(text: string, fromHost: string): FoundTv | null;

    opts?: { ssdpMs?: number /* 3000 */ }): Unsubscribe;

  export function samsungFromProbe(host: string, open: ReadonlySet<number>): FoundTv | null;
  /** Core-plan `BrandSetup.probeHost`: info page parses → FoundTv, else null. Rethrows notLocal. */
  export function probeSamsungHost(t: Pick<TvTransport, 'request'>, host: string): Promise<FoundTv | null>;

  // rediscover.ts
  export function rediscoverSamsung(
    t: Pick<TvTransport, 'ssdpSearch' | 'probe' | 'request' | 'open'>,
    link: Extract<TvLink, { kind: 'samsung' }>,

- Rules:
  - Found TVs are `{kind:'samsung', host, name:'Samsung TV', secure:true, usn?}`. The SSDP name stays
    generic; the real name is read at pairing.

  - `rediscoverSamsung` returns null at once without `link.mac`. Candidates come from SSDP and a
    `probe([8001, 8002])` in parallel, de-duplicated by host, never the link's own current host first
    (that is the caller's job). Each candidate is accepted only when **both** hold: its info page
    `mac` equals `link.mac` (lower-case compare), and `t.open('wss://<host>:8002/…', 1500,
    {pinSha256: link.pinSha256})` succeeds (URL built with `socketUrl(host, opts.token ?? '')`, so a TV
    that knows the token does not prompt) and is closed at once. A candidate that fails either check is
    skipped; at most `maxCandidates` candidates are checked; gives up after `giveUpMs`.

  `linkHost`, `notPaired` and `pinMismatch` latches, `observers`, `idleTimer`):
  - **supports:** false for any non-`samsung` link. `tv.key` and `tv.text` true. `tv.input` **false**
    (no input list; the screen sends the `input` key). `tv.powerOn` true only with `link.mac` and no
    `ir` link on the device (IR is the reliable path, as LG).
  - **capabilities:** `{ tv: { inputList: false, text: true, powerOn: !!link.mac || device.links.some(l => l.kind === 'ir') } }`.
  - **send tv.key / tv.text:** budgeted by `connectMs`; refuse if the signal is aborted; connect =
    token from `secrets.get(link.tokenRef)` (`null` → `notPaired`), `SamsungClient.connect(t,
    {host, token, pinSha256: link.pinSha256}, left)`, then `ready(left)`; reuse the open client;
    `key(KEY_NAME[k])`, `playPause` cycles `PLAY_PAUSE_CYCLE`; `text(cmd.text)`. A connect that sees
    `notPaired` from the TV (unauthorized / timeout event) sets the `notPaired` latch; a certificate
    mismatch (`notPaired` from `open`) sets `pinMismatch` and runs one rediscovery before latching.
    After a press, the client closes `idleCloseMs` later (any new press or observer cancels it).
  - **send tv.powerOn:** `t.sendWol(magicPacket(link.mac))`; no MAC → `unsupported`; errors →
    `notSent` (as LG's `asDeviceError`).
  - **observe:** while at least one observer is attached, `fetchInfo` runs immediately and then every
    `pollMs`. Success → `{kind:'tv', state:{power: info.power === 'on'}}`, emitted only when changed;
    a late observer gets the last state at once. Two consecutive failures → power false (not emitted
    when `t.onWifi()` resolves false: the phone is off the network, as LG). The last observer leaving
    stops the poll and, after `idleCloseMs`, closes the socket. No other state is reported (spec §5.3).
  - **Warm socket:** while observed and `power` is true, the driver keeps the socket open, and when it
    drops reconnects with `reconnectMs` backoff. After the list is exhausted it stops (so a TV that
    keeps prompting is not spammed) until the next press, `clearNotPaired`, or a new observer. It never
    reconnects while the TV is `'standby'` or `notPaired`.
  - **Rediscovery:** after two failed polls (and a link MAC), or a `pinMismatch`, at most once per
    30 s and one at a time across TVs, call `rediscoverSamsung` with the stored token. A new host →
    `entry.host = host` and `onHostChanged(device.id, host)` once. If a `pinMismatch` finds no other
    host, latch `notPaired` (a changed certificate at the same address is never trusted again
    silently).
  - **clearNotPaired(deviceId, link?):** clears both latches, adopts the new link's host, resets the
    backoff, and reconnects when observed (the core plan's `withTvFollowUp` calls it after a re-pair).
  - **forget:** closes the socket, stops polling, drops the entry, then `secrets.delete(link.tokenRef)`
    (idempotent, a failure is rethrown after the entry is gone). The pin lives on the link and needs
    no delete. Other devices are untouched.
