# Voice on every TV from the phone (research, 2026-11-02)

Goal: the mic button on the TV screen should work on every TV One Remote supports, within the
"local network only" privacy rule (no cloud, connections only to private addresses).

## Summary

There are two kinds of voice, and only one of them works on every brand.

1. **Real TV voice (the TV's own Assistant hears you).** The phone streams raw mic audio to the TV,
   and the TV's assistant handles it ("open YouTube", "turn on subtitles", search). Only **Android
   TV / Google TV** offers this over the local network. Whether the TV then needs the internet is
   the TV's business, not the app's.
2. **Dictation (the phone turns speech into text, then types it on the TV).** The phone does
   speech-to-text on the device, then sends the text through the TV's text-input channel. All three
   platforms we have already built have that channel, so this works on **LG, Samsung and Android
   TV**. It fills search boxes and text fields. It cannot run commands.

Recommendation: the mic does (1) on Android TV and (2) everywhere else, behind one button. Details
and open questions are below.

## 1. Android TV / Google TV: native voice (Remote Service v2)

Source: tronikos/androidtvremote2 (`remote.py`, `remotemessage.proto`, `voice_stream.py`), the
library our protocol code follows.

- **Feature flag:** `VOICE = 8` in the configure features. The TV only answers voice if both sides
  set it. Our `src/androidtv/constants.ts` sends `FEATURES = 103` (PING|KEY|IME|POWER|VOLUME) and
  marks voice a non-goal, so it would become `111`.
- **Start:** send `KEYCODE_SEARCH` (84). The TV replies `remote_voice_begin` (field 30) with a
  `session_id` (and the assistant's package name). Echo `remote_voice_begin{session_id}` back. The
  library waits 2 s for the reply, and no reply means the TV has no voice.
- **Audio:** `remote_voice_payload` (field 31) `{session_id, samples}`. The samples are 16-bit PCM,
  8 kHz, mono, sent in 20 KB messages. Messages under 8 KB are zero-padded, because the Nvidia
  Shield rejects smaller ones.
- **Stop:** `remote_voice_end` (field 32) `{session_id}`. One session at a time.
- **Phone side:** a mic capture at 8 kHz mono PCM16, which neither Expo nor our `lan-socket` module
  has today. Android `AudioRecord` and iOS `AVAudioEngine` both do it in a small native module.
  This needs `RECORD_AUDIO` on Android and `NSMicrophoneUsageDescription` on iOS.
- **Not yet known:** whether the Airtel Xstream box sets the voice bit (check the TV's configure
  `features` in a log) and whether its assistant works with phone audio. This needs a hardware test.

## 2. LG webOS: dictation only

- No local voice-audio API is documented. LG's own voice (Magic Remote mic, ThinQ app) goes through
  LG's cloud, and SSAP has no endpoint that accepts audio.
- Text input exists, and we already use it: `ssap://com.webos.service.ime/insertText {text,
replace}`, plus `sendEnterKey` and `deleteCharacters`. It only types into a field that is already
  open on the TV, such as the YouTube or browser search box.

## 3. Samsung Tizen: dictation only

- No local voice-audio API is known. Bixby and the SmartThings app voice go through Samsung's cloud.
- Text input exists over the same `ms.remote.control` WebSocket: `TypeOfRemote: "SendInputString"`
  with `Cmd` = base64(UTF-8 text) and `DataOfCmd: "base64"`, then `SendInputEnd`. Some TVs need a
  `ms.channel.emit` "text received" broadcast first (samsungtvws `send_text`). The samsung lane's
  `client.text()` already sends a text frame. It also only works while a text field is open on the
  TV.

## 4. Other platforms (not built yet)

- **Roku:** ECP has no audio, and the "search" command was removed in Roku OS 12.0. Roku also says
  ECP must not be driven from third-party mobile apps. A Roku staffer stated "no public APIs" for
  voice. The `Lit_` keyboard keys still type characters, so dictation could work there.
- **Fire TV:** voice goes through Alexa's cloud, and no local audio path is known. Text works over
  ADB (`input text`) once ADB debugging is enabled.

## 5. The phone's speech-to-text must stay on the device

The privacy rule rules out cloud speech recognition, so dictation has to run on the device:

- **iOS:** `SFSpeechRecognizer` with `requiresOnDeviceRecognition = true` (iOS 13+). Apple forum
  reports say offline results are sometimes inconsistent.
- **Android:** `SpeechRecognizer.createOnDeviceSpeechRecognizer` exists only on Android 12 (API 31)
  and later. The library jamsch/expo-speech-recognition says on-device mode is only verified on
  Android 13+, needs an installed language model, and recommends checking `getSupportedLocales()`.
  The test phone (RMX1901) runs **Android 11**, so strict on-device dictation may not be available
  there. `EXTRA_PREFER_OFFLINE` is only a preference, and the recognizer may still use the network,
  which would break the privacy rule.
- Candidate library: `expo-speech-recognition` (config plugin, `requiresOnDeviceRecognition`). It
  would be the app's first speech dependency.

Native voice on Android TV (section 1) has none of these limits, because the phone only records
audio and the TV does the recognition.

## Decisions (2026-11-02)

The user approved the approach: native voice on Android TV, and on-device dictation on LG and
Samsung. Their physical remotes' voice uses a private Bluetooth or radio link and the maker's
cloud, so it is not open to us. The three open questions were settled as defaults (Claude's calls,
which can be changed):

1. With no text field open on LG or Samsung, the app shows "Open a search box on the TV first". It
   does not guess an app to open.
2. On a phone with no on-device speech recognition (such as the Android 11 test phone), the mic is
   hidden for LG and Samsung. There is no cloud opt-in, so the "local network only" rule holds.
   Android TV voice still works on such a phone, because the TV does the recognition.
3. Hold to talk, release to send, as in Google's app.

LG and Samsung give no "no text field" signal, so dictation there sends blindly; only Android TV
reports it (as a `DeviceError` with detail `noTextField`).
